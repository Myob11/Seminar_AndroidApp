# Backend Task: Add FCM Push Notifications

## 1. Firebase credentials

Use the Firebase project configured for the Android app ID `com.example.seminarandroidapp`.

The backend needs permission to send FCM messages from that project:

- Enable the FCM HTTP v1 API.
- Configure the server with the Firebase Admin SDK or equivalent credentials.
- Prefer the hosting platform’s service identity where available. Otherwise, store service account credentials securely.
- Never include server credentials in the Android app or commit them to the repository.

References: [Admin SDK setup](https://firebase.google.com/docs/admin/setup) · [FCM HTTP v1 API](https://firebase.google.com/docs/cloud-messaging/send/v1-api)

## 2. Device registration API

After login, the Android app will register its Firebase Installation ID (FID) with the backend. To support multiple devices per account and allow logout from a single device, the app will also provide a locally generated installation ID.

### Register or update an installation

```http
PUT /api/users/me/push-installations/{installation_id}
Authorization: Bearer <existing JWT>
Content-Type: application/json
```

Request body:

```json
{
  "fid": "<Firebase Installation ID>",
  "platform": "android",
  "notifications_enabled": true
}
```

Upsert the installation for the authenticated user. Derive the user ID from the JWT; never accept a user ID from the request body. Repeated registrations must be safe and update the FID, notification permission state, and `last_seen_at`.

### Remove an installation

```http
DELETE /api/users/me/push-installations/{installation_id}
Authorization: Bearer <existing JWT>
```

Delete only the specified installation belonging to the authenticated user. The app will call this endpoint when the user logs out, before clearing its local session.

If the same app installation signs into a different account, associate the installation with the newly authenticated account.

### Suggested database fields

| Field | Description |
|---|---|
| `installation_id` | Unique UUID generated by the app for this installation |
| `user_id` | Authenticated account ID |
| `fid` | Firebase Installation ID |
| `platform` | For example, `android` |
| `notifications_enabled` | Whether notifications are allowed on the device |
| `created_at` | Registration creation time |
| `updated_at` | Most recent registration update |
| `last_seen_at` | Most recent successful registration sync |

Keep FIDs private. Do not expose them to other users or write them to application logs. Firebase recommends FID-based targeting and refreshing the server record when the FID changes. See [FID registration management](https://firebase.google.com/docs/cloud-messaging/manage-tokens).

## 3. When to send notifications

Send each push after the related database transaction commits.

| Existing backend operation | Push recipient | `data.type` |
|---|---|---|
| `POST /api/conversations/:id/messages` saves an encrypted message | Other conversation participant | `message_received` |
| `POST /api/friends/requests` saves a pending request | Request recipient | `friend_request_received` |
| `POST /api/friends/requests/:id/accept` saves acceptance | Original requester | `friend_request_accepted` |

These are existing REST routes, and the WebSocket already sends matching event types. Keep the WebSocket events for connected clients and add FCM delivery to the recipient’s registered installations.

The app may receive both a WebSocket event and a push while it is open, so it should avoid showing duplicate notifications in the foreground.

Queue FCM sends after the database commit. An FCM outage must not delay or undo message or friend-request creation. Retry temporary FCM failures with backoff. Remove an installation only when FCM confirms it is invalid or unregistered; do not remove a valid FID because of an unrelated payload error.

## 4. Notification payloads

Send a user-visible notification with string-valued data fields. Do not include message text, ciphertext, encryption keys, or recovery information.

### New message

```json
{
  "notification": {
    "title": "New message",
    "body": "You received a new message"
  },
  "data": {
    "type": "message_received",
    "conversationId": "<conversation UUID>",
    "messageId": "<saved message UUID>"
  }
}
```

### New friend request

```json
{
  "notification": {
    "title": "Friend request",
    "body": "You received a friend request"
  },
  "data": {
    "type": "friend_request_received",
    "requestId": "<request UUID>",
    "fromUserId": "<requester user ID>"
  }
}
```

### Friend request accepted

```json
{
  "notification": {
    "title": "Friend request accepted",
    "body": "Your friend request was accepted"
  },
  "data": {
    "type": "friend_request_accepted",
    "requestId": "<request UUID>",
    "byUserId": "<accepting user ID>"
  }
}
```

The Android app will use these IDs to open the relevant conversation or requests screen, then load current data through REST. Send notifications to all active FIDs for the recipient; push delivery must not depend on an active WebSocket connection.

## 5. Documentation and verification

Update the [backend API docs](https://backend.kbnet.si/api/docs) with the two installation endpoints, including authentication requirements, request and response bodies, and error responses.

Verify that:

- Registration can be repeated safely.
- A user can register multiple installations.
- A user cannot delete another user’s installation.
- Logout removes only the current installation.
- Each of the three operations sends the matching notification to the correct recipient.
- Invalid FIDs are removed when FCM identifies them.
- Push payloads contain no message content or encryption material.

## 6. Android client dependency

The Android client setup is separate from the backend work. It requires Firebase configuration, notification permission on Android 13 and newer, and an FCM service that registers the FID with the endpoints above.

References: [Android FCM setup](https://firebase.google.com/docs/cloud-messaging/android/get-started) · [Notification permission](https://developer.android.com/develop/ui/views/notifications/notification-permission)
